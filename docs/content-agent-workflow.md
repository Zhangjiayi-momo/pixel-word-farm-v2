# 词汇内容智能体工作流

## 目标

把教师上传的最小词条：

```text
单词 + 词性 + 中文释义
```

转换为可教学的标准词条：

```text
准确音标 + 标准中文释义 + 派生词及汉意 + 短语及汉译 + 每个短语对应例句
```

## 工作流

```mermaid
flowchart LR
    A["教师上传最小词表"] --> B["编码识别与字段归一化"]
    B --> C["有道词典主检索"]
    C --> D["派生词、短语和双语例句提取"]
    D --> E["短语逐条二次检索与例句匹配"]
    E --> F["缺失字段多源回退"]
    F --> G["质量规则校验"]
    G --> H["标记已核验或待教师复核"]
    H --> I["写入词库并缓存"]
```

## 数据源分工

| 数据源 | 主要用途 | 回退方式 |
|---|---|---|
| 有道公开词典接口 | 美式/英式音标、中文标准释义、派生词及汉意、短语及汉译、双语例句 | 主来源失败后切换其他来源 |
| Free Dictionary API | 英文释义、部分音标、例句 | 有道缺字段时补充 |
| Datamuse | 词形、关联词、发音元数据、常见前后搭配 | 自动补全和规则回退 |
| Tatoeba | 英文真实例句 | 词典无例句时补充 |
| MyMemory | 英文词形或短语的中文翻译 | 派生词、短语缺少汉译时回退 |

## 质量规则

1. 音标必须来自词典字段；使用 Datamuse 发音回退时标记“待教师复核”。
2. 派生词必须与词根相关，并带有中文释义。
3. 短语必须来自词典短语字段或经过筛选的常见双词搭配。
4. 每个短语优先查找包含完整短语的例句，而不是任意包含首词的句子。
5. 例句同时保留英文和中文翻译。
6. 任一关键字段缺失时，`enrichment.needsReview` 设为 `true`。
7. 教师原始中文释义作为输入依据保留；在线结果不能静默覆盖教师的人工修改。

## 输出结构

```json
{
  "word": "sentimental",
  "phonetic": "/sentəˈmentəl/",
  "meaning": "多愁善感的；感伤的",
  "derivatives": [
    ["sentimentality", "多愁善感"],
    ["sentimentalism", "感情主义；沉于情感"]
  ],
  "phraseExamples": [
    {
      "phrase": "sentimental value",
      "meaning": "情感价值",
      "example": "This ring has great sentimental value for me.",
      "translation": "这枚戒指对我来说很有纪念意义。",
      "source": "《牛津词典》"
    }
  ],
  "enrichment": {
    "providers": ["有道词典", "Datamuse 发音回退"],
    "needsReview": false,
    "verifiedExampleCount": 1,
    "phraseCount": 1
  }
}
```

## 维护约定

- 所有外部请求都经过 `server.py`，浏览器不直接访问第三方接口。
- 结果缓存到 `runtime/enrichment_cache.json`。
- 更换检索规则时提升缓存版本号，例如 `v8`、`v9`。
- 新增数据源时保持统一输出结构，不修改前端词卡结构。
- 新增题型时读取统一的 `phraseExamples` 和 `example` 字段。

## 后续 AI 接入点

可以在现有流水线后增加一个可选的 GPT/Codex 审核与改写节点：

1. 输入原始词条和在线检索结果。
2. 删除不相关派生词和错误搭配。
3. 将英文标准释义翻译为简洁中文。
4. 为每个短语生成一条适合高考语境的例句。
5. 输出结构化 JSON，而不是自由文本。
6. 所有 AI 修改标记来源，并默认进入教师审核队列。

API Key 只能放在服务器环境变量中，不能进入浏览器代码。
